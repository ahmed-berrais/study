Explicit (cast) required when you can lose information (e.g. float/double → int):

4. Chapter 2: class, object, attributes, methods (slides 35–51)

Object (slides 36, 49)

An entity manipulated in a program by calling its methods. It has:

  • Identity: unique, distinguishes it from all others (it can be named/referenced).
  • Type: its class.
  • State: values of its attributes at a given time.
  • Behaviour: its methods (consultation = getters, update = setters).

An object is an instance of a single class; any method of that class can be applied to it.

Class (slide 37)

A family of objects with the same structure and behaviour, with a name. Lets you create (instantiate) as many objects as you want. Convention: ClassName objectA.

Class example (slides 38–40)

```java class public class Person { // attributes: visible in ALL methods of the class public String name, lastName; public int age; // method that returns nothing → void public void setName(String aName) { name = aName; } // method that returns a String public String getName() { return name; } } ```

Declaring a method (slides 40–47)

Syntax[public/private/protected] [static] <return type> methodName(<type1 p1, type2 p2, …>) { <method body> }
  • Return type: a simple type or a class name: double min(double a, double b), int[] first(int n), Color getColor().
  • void if it returns nothing: void display(double[][] m).
  • Parameters: empty () or comma-separated type name pairs.
  • If the return type isn't void, the body must contain a return expression; compatible with the type. Several returns are allowed.
  • In a void method, return; just exits early.
```java members // several returns double min(double a, double b) { if (a < b) return a; return b; } // return; to leave a void method early (slide 45) void showPosition(int[] tab, int val) { for (int i = 0; i < tab.length; i++) { if (tab[i] == val) { System.out.println("Position of " + val + " is " + i); return; } } System.out.println(val + " is not in the array"); } ```
Local variables (slides 46–47)Declared inside a method; store the data the method uses; only accessible in their block; their value is lost when the method ends. Two different methods can use the same local name (int i in both) without conflict. Two different classes can have members with the same name (Point.x and Circle.x): Java knows which one from the object's type.

Creating objects = instantiation (slides 50–51)

3 steps:

  1. declare a reference variable of the class type,
  2. new allocates memory,
  3. a constructor creates and initialises the object.
RuleObjectType objectName = new Constructor(parameters);
```java nocheck MyClass myObject = new MyClass(); Person john, peter, x; // 3 references, NO objects yet john = new Person(); // now an object exists peter = new Person(); x = new Person(); john.setName("John"); // dot "." to access members System.out.println(john.getName()); ```

5. Constructors & object destruction (slides 52–62)

Constructor: the 6 rules (slide 52), learn them as a list
  1. Special method called only once per object, at creation (new).
  2. Has the same name as the class.
  3. Role: initialise the attributes.
  4. Generally public, no return type, not even void.
  5. A class can have several constructors, differing in number/type of parameters (= overloading).
  6. If you write no constructor, Java gives a default constructor with no parameters that sets attributes to 0 (numbers), null (references/String), false (boolean). As soon as you write one, the default one disappears.
```java class public class Person { public String name; public int age; public Person(int x) { // constructor 1 age = x; } public Person(String s) { // constructor 2 name = s; } public Person(String s, int x) { // constructor 3 name = s; age = x; } } ```
```java nocheck Person p1 = new Person(10); // → constructor 1 Person p2 = new Person("Ali", 10); // → constructor 3 Person p3 = new Person("Ali"); // → constructor 2 Person p4 = new Person(); // ✗ COMPILE ERROR: // no constructor without parameters exists any more ```
⚠ Slide 54 trapBefore you add Person(String, String, int), new Person() works (default constructor). After you add it, the same line is a compilation error. Fix: also write public Person() { }.

Object destruction: Garbage Collector (slides 60–61)

  • Other languages have a destructor that frees the resources the constructor allocated.
  • In Java it's automatic: the Garbage Collector (GC).
  • An object can be destroyed when no reference points to it any more (e.g. obj = null;).
  • You can ask for it explicitly with System.gc(); (the JVM decides when it really runs).
```java nocheck Date dt = new Date(1, 6, 1997); dt.show(); dt = null; // the object has no reference any more: // it's unreachable, the GC may destroy it System.gc(); // ask the GC to run ```

6. The keyword this (slides 63–64, Lab 3 Ex4–5)

this = reference to the current object, the object whose method is running.

Use 1: remove ambiguity (parameter hides attribute)

```java nocheck public Point(double x, double y) { x = x; // ✗ assigns the parameter to ITSELF y = y; // the attributes stay 0.0 } ``` ```java class class Point { double x, y; public Point(double x, double y) { this.x = x; // ✓ attribute = parameter this.y = y; } } ```

Use 2: call another constructor: this(...)

```java class class Point { double x, y; public Point(double x, double y) { this.x = x; this.y = y; } public Point() { this(0, 0); // MUST be the FIRST statement } } ```

Use 3: return the current object (method chaining, Lab 3 Ex4)

```java class class Student { int id; String name; public Student(int id, String name) { this.id = id; this.name = name; } public Student incrementAndReturnId() { id++; return this; // returns the object itself } public void display() { System.out.println("Student ID: " + id + ", Name: " + name); } } public class TestStudent { public static void main(String[] args) { Student s1 = new Student(7, "Amine"); s1.incrementAndReturnId().display(); // Student ID: 8, Name: Amine } } ```

Encapsulation (slide 76)

DefinitionEncapsulation brings data and methods together in one structure (the class). Implementation details are hidden: the outside world accesses the data only through a set of operations (the object's interface: public methods). It guarantees the integrity of the object's data.

Lab 3 Ex1: why it doesn't compile

```java nocheck class BankAccount { private String accountNumber; private double balance; } // in main, another class: myAccount.accountNumber = "ACC-100203"; // ERROR 1 myAccount.balance = 500.0; // ERROR 2 ```

Why: the attributes are private, so they're only accessible inside BankAccount's own methods. main is in another class → "has private access" compile error.

The fix: getters/setters (+ validation)

```java class class BankAccount { private String accountNumber; private double balance; public String getAccountNumber() { return accountNumber; } public void setAccountNumber(String accountNumber) { this.accountNumber = accountNumber; } public double getBalance() { return balance; } // no setBalance! public void deposit(double amount) { if (amount > 0) { balance += amount; } else { System.out.println("Invalid amount"); } } } public class Ex1_Encapsulation { public static void main(String[] args) { BankAccount myAccount = new BankAccount(); myAccount.setAccountNumber("ACC-100203"); myAccount.deposit(500.0); System.out.println("Account Number: " + myAccount.getAccountNumber()); System.out.println("Current Balance: $" + myAccount.getBalance()); } } ```
🎯 Getter / setter pattern (write it without thinking) public Type getX() { return x; } · public void setX(Type x) { if (valid) this.x = x; } · for a boolean: isX(). Why it's better than a public attribute: the setter can refuse invalid values (negative balance, battery > 100…), and you can make an attribute read-only (getter without setter).

8. Scope of variables (slides 72–73)

```java nocheck public class AClass { int i, j, k; // attributes: known everywhere in the class public void sth1(int z) { int j, r; // local j HIDES the attribute j r = z; j = z; // → the LOCAL j } public void sth2() { k = r; // ✗ ERROR: r only exists in sth1 } } ```
  • A variable is known only in the block { } where it is declared (and nested blocks).
  • Attributes (declared in the class) are known in every method.
  • Name conflict local vs attribute → the most local one wins. Use this.j to reach the attribute.
  • for (int i = 0; …): i dies at the end of the loop.

9. Method overloading (slides 74–75)

  • Definition: several methods with the same name in one class.
  • They must differ by the number and/or types of parameters.
  • The return type may differ, but never as the only difference.
  • Several constructors = a special case of overloading.
  • Also called static polymorphism (the compiler chooses the method from the arguments).
```java nocheck int f(int x) { ... } double f(int x) { ... } // ✗ only the return type differs ```
```java members int solde; public void deposit(int amount) { solde += amount; } public void deposit(double amount) { solde += (int) amount; } public void deposit(int amount, String msg) { // different count solde += amount; System.out.println(msg); } ```

Lab 2 Ex2: calculateExpressCost(boolean isExpress) is described as "an overloaded version" of calculateBaseCost() (same idea, different parameters).

10. static and final (slides 67, 69)

```java class public class Counter { static int count = 0; // ONE copy shared by all objects final int ID; // constant per object public static final double PI = 3.14159; // class constant public Counter() { count++; ID = count; // a final attribute is set once } static int square(int x) { // class method: no object needed return x * x; } public static void main(String[] args) { new Counter(); new Counter(); Counter c3 = new Counter(); System.out.println(Counter.count); // 3 System.out.println(c3.ID); // 3 System.out.println(Counter.square(4)); // 16 } } ```
  • static attribute = class attribute: one value for the whole class, e.g. a counter of created objects. Access: ClassName.attr.
  • static method = class method: called without an object (Math.sqrt(x), Math.random(), main).
  • A static method can't use non-static attributes or this directly. That's why main must create an object first: Time t = new Time(5); t.display();
  • final = constant; must be initialised (at declaration, or in the constructor for an attribute). Re-assigning it → compile error.

12. Short answers to learn by heart (questions de cours)

QuestionAnswer to write
What is OOP?Representing real-world elements as objects (data + processing) with a high level of abstraction; a program is a set of interacting objects. Data-driven, not process-driven.
Why is Java portable?javac compiles the source into bytecode, which the JVM executes; a JVM exists for each OS, so the same bytecode runs everywhere.
JDK vs JRE vs JVMJVM executes bytecode; JRE = JVM + standard libraries (to run); JDK = JRE + development tools (javac, javadoc, jdb…) (to develop).
Class vs objectClass = mould/model (structure + behaviour); object = a concrete instance of the class with its own state and identity.
Attribute vs local variableAttribute: declared in the class, known in all methods, lives with the object, default value. Local: declared in a method, known only in its block, lost at the end, no default value.
What is a constructor? Differences with a method?Same name as the class, no return type, called automatically once at creation by new, initialises attributes. A method has a return type (or void) and can be called many times.
Default constructor?Provided by Java only if no constructor is written; no parameters; sets 0/false/null. Disappears as soon as one constructor is defined.
Uses of this?(1) access an attribute hidden by a parameter (this.x = x), (2) call another constructor of the same class, first statement (this(0,0)), (3) return/pass the current object (return this;).
Encapsulation?Data + methods in the class, details hidden (private), access only through public methods → integrity of the data.
Overloading?Same method name, different parameter list (number/types). Return type alone isn't enough. = static polymorphism.
static?Belongs to the class, not to an object: one shared copy (attribute) / callable without an object (method).
Garbage collector?Automatic mechanism that frees the memory of objects no longer referenced (obj = null); can be requested with System.gc().
while vs do…whilewhile tests first (0 or more turns); do…while tests at the end (at least 1 turn).

14. ⚠ Errata: mistakes in the slides/labs (don't copy them)

  1. Slide 18: float f = 1.5; doesn't compile (1.5 is a double) → float f = 1.5f;
  2. Slide 24: public int variable ==20; → = 20 (== compares, = assigns).
  3. Slide 27: system.out.println(i) → System.out.println(i); (capital S + semicolon).
  4. Slide 41/42: setColor(color c) → by convention the class is Color.
  5. Slide 55: Public Person(...) → public (lowercase, Java is case-sensitive).
  6. Slide 66: "private = class restricted to its package; default is private". Real Java: a top-level class is public or has no modifier (package/friendly). private class X at top level doesn't compile. If asked: "public = all classes; no modifier = same package only".
  7. Slide 56: class Circle() and public class MyProgram() → no parentheses after a class name.
  8. Slide 58: a method named double() is illegal (double is a reserved word) → doubleLength().
