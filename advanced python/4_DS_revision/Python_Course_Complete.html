1. Theory of Chapter 0 ★

Software

Software = a set of instructions (code) that tells a computer exactly what to do, step by step.

Application softwareSystem software
Programs you use directly: Instagram, Word, a calculator, a game.Runs in the background so everything else works: Windows, macOS, Android.

Software Engineering — the 6 phases of the lifecycle

Software engineering = the discipline of designing, building, testing and maintaining software in an organised, reliable way (not just "writing some code").

#PhaseQuestion
1RequirementsWhat should it do?
2DesignHow will it be built?
3ImplementationWrite the code
4TestingDoes it work correctly?
5DeploymentRelease it to users
6MaintenanceFix bugs, add features

Why it matters: banking (a bug sends money to the wrong person), hospitals (records must be accurate, available and secure), flight booking (a crash = lost seat), cars, elevators, traffic lights…

Information System (IS) — 5 components

An IS is not just software: it combines Hardware + Software + Data + People + Process to produce useful information.

ComponentMeaningSchool portal example
Hardwarephysical machines (computers, servers, phones)the servers
Softwareprograms that run on the hardwarethe website
Dataraw facts: names, numbers, dates, transactionsthe grades
Peopleeveryone who uses or maintains itstudents, staff
Processthe steps followed to get work donehow grades are entered

Food delivery app → Data = your order, your address, the restaurant's menu prices.

Where data science fits: Collect → Store → Analyse → Decide

1 the IS collects data (orders, clicks, sensors) · 2 data is stored in files/databases · 3 we use Python to analyse it (this course) · 4 people decide better.

Why Python? How does it run?

  • Reads like English, beginner-friendly, huge community, extremely versatile (data science, web — Instagram/Spotify servers, automation, AI/ML, games).
  • Java needs a class + main + System.out.println (4 lines) — Python: print("Hello!") (1 line).
  • Python is interpreted: you write code → the interpreter reads it line by line, top to bottom → you see the result immediately. No separate compile step → notebooks (Jupyter/Colab) are interactive.

5. if / elif / else ★

Python checks conditions top to bottom; the first True block runs, the rest are skipped. else catches everything else. The colon : and the indentation (4 spaces) are mandatory.

temperature = 8
if temperature > 30:
    print("It's hot!")
elif temperature > 15:
    print("Nice weather.")
elif temperature > 0:
    print("A bit cold.")
else:
    print("Freezing!")
A bit cold.
score = 55
if score >= 60:
    print("Pass")
elif score >= 50:
    print("Retake")      # first True condition
else:
    print("Fail")

# one-line (ternary) form
status = "adult" if age >= 18 else "minor"
Retake
Order matters: test the most specific case first. In "even/odd/zero", check n == 0 before n % 2 == 0, otherwise 0 is printed as "Even". Two separate ifs can both run; if/elif runs only one.

def total_price(price, quantity, discount=0):     # discount has a default value
    """Return the price after discount."""
    total = price * quantity
    return total * (1 - discount / 100)

Never replace all missing values by 0: it creates fake data and biases the averages (a price of 0, an age of 0 don't exist). Median > mean when there are outliers (robust). Document every choice. isna() = isnull() (aliases); notna() = the opposite.

errors="coerce" turns invalid values into missing (NaT for dates, NaN for numbers) instead of crashing. The right types unlock the .dt and .str tools. A column with NaN cannot be int64 (NaN is a float) → that's why quantity is read as 1.0, 2.0.

Outliers — business rule beats statistics

orders["quantity"].value_counts().sort_index()        # see the 999

# statistical rule (IQR):
q1, q3 = orders["unit_price"].quantile([0.25, 0.75])
iqr = q3 - q1
outliers = orders[(orders["unit_price"] < q1 - 1.5 * iqr) | (orders["unit_price"] > q3 + 1.5 * iqr)]

Ask: is 999 a real order or a data-entry error? Who can confirm?

Group-wise imputation with transform ★

by_product = orders.groupby("product_id")["unit_price"]
median = by_product.transform("median")        # a column ALIGNED with the rows (same length)
orders["unit_price"] = orders["unit_price"].fillna(median)
groupby(...).median() → one value per product (short table). groupby(...).transform("median") → the product's median repeated on every row → perfect for fillna.

A reusable cleaning function

def clean_orders(raw):
    df = raw.drop_duplicates().copy()
    df["order_date"] = pd.to_datetime(df["order_date"], errors="coerce")
    df = df.dropna(subset=["order_date"])
    df = df[df["quantity"] <= 10]
    df["payment_method"] = df["payment_method"].fillna("Unknown")
    return df

orders = clean_orders(pd.read_csv("data/orders.csv"))   # same input -> same output, every night

Modern pandas good habits (pandas 3)

  • Copy-on-Write: a filtered DataFrame is a safe copy; add .copy() when you plan to edit it (avoids SettingWithCopyWarning in pandas 2).
  • String dtype: text columns use a dedicated str dtype by default.
  • Avoid inplace=True: assign the result back: df["a"] = df["a"].fillna(0).
  • Method chaining: df.assign(total=df.q * df.p).query("total > 100").sort_values("total").
  • Keep the raw data: work on clean = raw.copy().

Industry: banking (duplicated transactions → wrong balances, false fraud alerts), healthcare (different date formats → wrong patient timelines), telecom (missing usage records → under-billing), retail (typos in city names → wrong regional reports).

  • df.shape, df.columns, df.dtypes, df.size are attributes (no parentheses); df.info(), df.head(), df.describe() are methods.

  • A pandas method returns a new object: df.dropna() alone changes nothing → df = df.dropna().
